## Changes

- Recovery opens a connection-specific view, clears the prior search and refreshes saved routes.
  The pinned account and model stay visible in a current-connection card; other saved connections
  remain filtered by existing Space policy and authorization. Runtime model/permission controls
  remain in the normal Runtime settings view.
- Managing the pinned connection selects its exact saved profile ID. It neither activates another
  account nor repairs, rotates or sends credentials. An unavailable requested identity is explained.
- Authentication and exhausted allowance have separate sanitized recovery states and guidance.
  A new classified 402 replaces stale 403 state; an ordinary failure retains the known blocker,
  and a successful turn clears it.
- Personal transfer and in-place model selection require confirmed native-image support when the
  copied history requires it. Incompatible/unknown personal targets are refused before confirmation,
  default changes or fork RPCs. Accepted live images missing strategy metadata are treated
  conservatively until history reload; explicit vision-sidecar text does not impose this requirement.
  The host's existing authorization and image-history checks remain authoritative.
