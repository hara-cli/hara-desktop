# Hara Workspace 交互与隔离设计

状态：设计原型与契约样例，尚未接入生产。2026 年 10 月 14 日。

Hara 以 Workspace 为唯一业务容器。所有 Workspace 对等，使用相同的数据模型、基本权限和隔离标准。一个人加上 Hara 就能开始；邀请人类或 AI 同事只改变成员构成，不切换成另一套企业产品。能力档位影响可用功能与额度，不改变身份层级。

## 用户入口

桌面端和网页端共用信息架构：Workspace 切换、聊天、任务与工单、空间设置。主 Hara 使用品牌标识独立置顶；频道人类消息、AI 消息与私聊采用相同消息结构，AI 始终有明确标识。右侧成员、任务和执行依据按需展开，不占据默认聊天宽度。

单一空间时直接进入聊天。切换器显示名称和能力档位，不把模型套餐名当成工作空间名称。新建 Workspace 不复制旧空间的同事、记忆、文件、Key 或授权。私人频道与基本权限不是高价档位专享。

普通聊天不自动建立任务，人类之间的私聊不唤醒 AI。明确 @、任务指派或受授权事件才唤醒负责人。主 Hara 可以安排同事，获授权同事也能直接负责；不把每次发言都广播给所有 Agent。

## 连接与 Key

所有模型连接都在当前 Workspace 的同一设置页管理，一个空间可有多个连接和一个新任务默认连接。直连和管理连接是连接来源，不是个人或企业空间类型。受管理连接仍由服务端治理，普通成员不能读取管理密钥或解除限额。

Hara 客户端不得接收管理端真实模型 Key。凭据由受信宿主或服务保存，界面只获得脱敏状态和连接 ID；密钥不得进入聊天、Agent 人格、普通日志或浏览器持久存储。编辑、轮换、撤销和访问密钥分别鉴权。

原型只有合成凭据引用，不接收真实 Key。正式密钥箱的系统钥匙串、加密和恢复流程仍需单独实现验收。

### 用户确认：相同 Key 不合并空间（2026-10-14）

每个新 Workspace 都要独立新增模型连接，即使填入的供应商 Key 与另一空间完全相同。
连接 ID、私有凭据引用、凭据代次、默认模型、限额策略和本地撤销状态分别保存；不得按 Key
正文、哈希、供应商账号或登录用户自动去重、继承或发现另一空间的连接。切回已经配置的
Workspace 时恢复它自己的设置，不要求每次切换重填 Key，也不自动重新授权旧运行。

企业托管连接同样在本空间「模型与连接」管理。管理员新增、轮换托管凭据；普通成员申请
本空间的模型使用权，批准后只获取受限授权，不获取企业原始 Key。托管连接必须与服务端
验证的 Workspace 归属一致，不能把一个企业 Token 随意挂到其他空间。

账号只承担统一登录身份。Membership 以 `(workspaceId, accountId)` 为边界，各自具有角色、
权限、状态和撤权修订：同一个人可以在 A 是管理员，在 B 是普通成员，在 C 没有成员身份。
创建或管理 A 不能授权读取 B；退出或撤销 A 的成员资格也不自动修改 B 的角色。每次服务端
读写和执行都检查目标 Workspace 的当前成员权限，不从全局账号角色或前台选中空间推断。
消息、Agent 人格与记忆、文件、任务/工单、连接器、批准、索引/缓存、预算和审计均遵守
原空间与受众边界。此段是产品与验收要求，不宣称现有兼容代码已经完成全量隔离。

相同供应商 Key 可能共享上游额度；在供应商处撤销该 Key 可能使两处连接都失效。Hara
内部数据隔离不能被表述为上游账号、账单、数据留存或物理文件实体已经独立。

## 业务对象

| 对象 | 归属和职责 |
| --- | --- |
| Workspace | 稳定不透明 ID、名称、存储位置、能力档位、策略修订；没有父空间或隐式继承 |
| Membership | 人类账号或 AI 主体在本空间的角色、状态和修订；A 的管理员不是 B 的管理员 |
| WorkspaceAgent | 本空间稳定员工身份、昵称、人格和分区记忆；不以模型连接或终端 Session 作为身份 |
| ModelConnection | workspaceId、连接 ID、路由方式、模型策略、私有 credentialRef 和凭据代次 |
| Conversation | workspaceId、频道或私聊、成员与可见性；消息正文和附件遵守同一受众边界 |
| Task 和 Ticket | workspaceId、来源消息、负责人、资源范围、结果、验收与工单关闭条件 |
| RuntimeBinding 和 Run | 员工、宿主、引擎、原生 Session、连接代次、目录与执行授权的精确绑定 |
| Approval 和 Receipt | 原空间、对话、任务修订、动作摘要、真人、有效期和一次性消费记录 |

同一 AI 员工可以接入多个 Runtime。每次运行固定具体绑定；新任务默认变化不替换旧运行。Codex 和 Claude Code 保留各自的账户授权；OpenCode 和 Pi 沿用 Hara 受控模型及工具边界。现有终端自动发现不等于可接管，任意 tmux 会话也不能被推定属于当前空间。

业务 Workspace 与代码目录不是同一个概念。当前 CLI 的文件路径 workspace 工具继续承担目录安全；新业务边界使用 workspaceId，目录使用 workdir/resource grant，避免只靠当前 cwd 推导成员或密钥权限。

## 隔离范围

| 资源 | 正式实现必须约束的边界 |
| --- | --- |
| 消息和历史 | 按 Workspace 和对话受众读写；旧响应不能写入新选中的空间 |
| 人格和记忆 | 索引、摘要、检索缓存与结果同时校验 Workspace 和受众；不汇总私聊权限 |
| 模型和 Key | 只解析当前运行绑定的连接；缺失、撤销或代次变化不借用全局或其他空间连接 |
| 任务和工单 | 列表、详情、领取、评论、文件、通知、结果和验收都在服务端检查归属 |
| 执行资源 | 进程、队列、worktree、临时文件、环境、原生 Session 和工具授权按 Run 绑定 |
| 连接器 | 邮箱、飞书、微信及外部服务按空间与目标连接建立独立授权和消费游标 |
| 批准和回执 | 绑定原空间、受众、动作、权限代次和期限；不从前台选择重新解释旧批准 |
| 预算和审计 | 整项任务累计所有委派消耗；同事切换或失败不得重置预算与未核销回执 |

切换 Workspace 只改变前台视图，不把后台任务换成新 Key，也不自动终止别的空间任务。撤权不同于切换：下一次受保护操作必须检查当前权限；不能因 Run 固定旧绑定而继续使用已撤销的凭据。

用户明确把同一外部账号或物理目录授权给两个空间时，提供商额度和文件实体可能共享。产品不能宣称这会创造两个独立的提供商账号或 OS 沙箱。要求强进程或宿主隔离时另用隔离执行端、容器或虚拟机，并单独验证。

设备层只保留账号登入、应用更新、语言外观和操作系统权限等公共基础设施。系统权限不自动授予任意 Workspace，必须再经过本空间和本次运行授权。

## 切换交互

每个 Workspace 保留自己的目录、选中对话、草稿、未读、设置和待处理任务。全局切换器可显示本人有权进入的空间名称及计数，不展示其他空间的私有消息或 Key。

未完成任务留在原空间。需要批准时，通知带原空间标识；用户返回原对话后处理。切换、取消或成员修订变化后到达的旧回调，不能用当前页面的 workspaceId、模型或成员角色重新授权。

一名 Agent 可以提供一个连续聊天入口，但模型上下文按任务分段、摘要和检索。UI 隐藏日志不等于减少 Token，整项任务的真实输入输出需另行评测。

## 任务闭环

频道请求关联到 Desk 工单或任务，由获授权负责人安排执行。普通消息仍是消息；Task、运行、定时触发与工单不是同一种对象。

引擎受理不代表执行完成；提交结果不代表验收完成；软件发布不代表用户已验证。卡片显示真实状态，结果提交后进入 review，独立验收后才完成。付费调用、对外发送或发布结果未知时保留回执，不自动重放。

Desk 是任务状态来源；Collab 或选定消息后端是消息来源。一个频道只选一个权威消息源。网页可以逐步以 desk.nanhara.tech 为统一入口，各服务通过版本化接口连接，不共用可写数据库。

## 现有代码需要迁移的部分

当前 `hara-cli/src/profile/profile.ts` 把所有 BYOK profile 映射为 `personal`，gateway profile 再映射到 org Space。Profile 同时承担连接与空间切换，不能仅改文案达到新的边界。`organization-bound.ts` 已有的服务端策略、冻结绑定和撤权检查应保留到统一连接层。

当前 Desk 的 Agent 是按用户、设备和客户端隔离的执行身份，不等于持久 AI 员工。保留它的凭据和 Session 隔离，增加 WorkspaceAgent 到执行身份的映射，不能让 Codex、Claude 和 Hara 共用长期 Token。

Collab 已有 M1e 文字频道、成员投影与游标同步。完整私有频道、私聊、未读、Agent 主体和批准尚须继续实现。现有 Desk 单部署单组织也不能直接改成多租户；先通过明确 Workspace 绑定保持原部署边界，再另行评审托管多租户。

## 迁移顺序

1. 建立稳定 Workspace 注册表与旧 Space ID 映射。旧个人资料完整保留在一个兼容 Workspace；不把每个旧 Key 自动拆成新空间。旧组织来源保持原组织边界，界面改为对等 Workspace。
2. 将模型连接显式绑定 Workspace，保留连接 ID、管理来源和策略。用户需要拆分时明确选择目标；没有归属证据的连接、联系人或连接器进入只读待确认，不按名称、cwd 或最近活跃猜测。
3. 迁移对话、人格、记忆、任务、索引、连接器、临时数据与授权。复制历史是单独的跨空间导入，展示目标与范围，不能自动发送或继承执行权限。
4. 旧运行沿用原映射和会话，不在运行中重写空间或原生 ID。迁移需备份、日志、并发保护、恢复验证和回滚，生产数据与服务 rollout 单独批准。
5. 发布 workspace.v2 能力协商后接通新 UI。旧引擎只显示兼容视图或要求升级，不以 UI 过滤替代服务端权限。

现有修复版与 Workspace 迁移分开发布，不能把本设计混进待签名的维护版本。

### 当前候选源码盘点（2026-10-14）

本段是对 Desktop Workspace 隔离工作树的源码审查，不是正式安装包、原生视觉或新功能
上线验收。候选已移除独立项目主导航、微信群 Agent 设置、能力中心重复的工作台/定时/
群组/文档卡片，以及独立编程启动入口；定时导航默认隐藏，侧栏管理已收进外观高级选项。
这些已经完成的入口精简不应重复计为待删除功能。旧 Office、项目及执行恢复代码仍有
实际调用者，不能把「没有主导航」误判成「全部代码已经废弃」。

下一批建议按以下边界收敛，尚未在本轮修改对应业务 UI：

| 现存入口或概念 | 建议 | 必须保留 |
| --- | --- | --- |
| 能力中心的 Hara、组织、市场三个页签 | 当前 Hara 页仅重复电脑使用入口，组织页重复模型/Desk 状态，市场页只是提示；收掉这些目录页，默认直达 Skill 与扩展管理 | Skill、扩展启停、插件工作面板、真实电脑权限设置 |
| 个人直连/企业连接及添加企业后的空间跳转 | 统一为当前 Workspace 的模型连接；加入空间、申请使用权与选择模型分开 | 托管凭据保护、服务端成员/策略验证、过期/撤权与旧连接恢复 |
| 应用更新页中的全局编程执行器偏好与 Agent Runtime 设置 | 日常选择归 Agent，Workspace 管理允许的 Runtime；旧编码工作者偏好先折叠进兼容高级设置 | 设备上引擎的安装/版本状态，编码工作者和 Agent Runtime 的语义区别，原生 Session 精确绑定 |
| 新建同事仍默认打开完整人才市场 | 改为主 Hara 提问或轻量创建，按需求展示少量推荐；完整目录作为可选展开 | 候选能力参考、明确雇佣/配置、权限批准，不能通过模板自动授予工具 |
| Office 模板主页与独立交付物/目录模式 | 不再作为平行聊天中心；文件从结果消息、右侧预览与本空间资源搜索打开 | 编辑、版本、导出、历史与原文件；不让文档模式冒充 Agent 列表 |
| 群组中的第二套组织/连接选择 | 融入当前 Workspace 的频道、成员和任务入口；组织管理回本空间设置 | Collab 的权威消息源、Desk 任务/工单状态、服务连接和独立鉴权 |
| 业务学习的个人/项目/企业平行入口 | 审核台账收进 Workspace 知识/规则的高级管理；Agent 私有记忆仍单独授权 | 证据、人工/管理员审核、撤销与审计；知识、规则和私聊记忆不能直接混成一库 |
| 固定核心导航的显示、隐藏与排序管理 | 固定主导航不必反复配置，只保留扩展快捷方式的高级定制 | 已存偏好、恢复路径、暂时不可用插件的设置，不重置用户状态 |

第一批可优先处理能力中心空/重复页、应用与 Workspace 设置分层，以及 Runtime 选择的
信息层级。独立会话总台只保留执行详情/高级恢复，不删除原生 Session；定时计划留在
Workspace 设置或 Agent 详情，执行结果关联业务任务，不能与工单状态各维护一套。
目标主导航是聊天/频道、任务与工单，Workspace 切换和固定设置入口始终可达；尚无后端
支持的页面不做假入口或以 UI 过滤冒充成员隔离。

真正删除旧实现须先确认调用方已迁移、历史/备份可恢复、在途运行不受影响、旧客户端和
权限边界有回归。批准、预算、取消/物理排空、任务闭环、错误恢复和私有数据边界不是冗余。

## 业务服务端技术建议（2026-10-14，待独立实施）

建议 Hara Workspace/Desk 的业务 API 采用 TypeScript/NestJS。当前 Control 与 Collab
已使用 NestJS，Desk 0.9.0 使用 TypeScript、node:http 与 pg；不必为换语言重写现有任务
状态、租约、结果、审批、事务或数据库。新领域模块可渐进组织为 Workspace/成员、
Agent/Runtime 注册、模型连接、任务/工单、连接器、批准和审计。
Nest 的 [模块](https://docs.nestjs.com/modules) 与 [Guard](https://docs.nestjs.com/guards)
是组织与入口机制，不自动提供空间隔离、幂等、事务内授权或可靠工作流。

保留现有 PostgreSQL 及各服务的权威数据边界，通过版本化 API、outbox 和去重回执连接；
统一技术栈不等于合并可写数据库或立即拆更多微服务。账号身份可共享，角色按
`(workspaceId, accountId)` 验证；连接、消息、文件、执行、预算和批准检验原空间归属。
旧 Desk 单组织部署不因换框架变成多租户；备份恢复、数据迁移和生产 rollout 单独验收。

Go 只在远端执行 daemon 成为明确需求且实测部署/资源收益足够时用于独立窄模块；Rust
保留于现有 Tauri/系统层，未来针对测得的热点再评估。没有 benchmark 支持当前全盘迁移，
换语言不会自动减少模型上下文或 Token。Pi/其他 Runtime 保持独立接口，不强制跟业务 API
使用同一框架。本节只记录选型建议，没有修改服务、安装依赖、迁移数据库或部署。

## 原型与验证

原型源码位于 `design/workspace-first/`，使用现有 Hara Logo 与克制的消息式布局。它只处理内存合成数据，刷新会重置；不会读取用户配置、接收真实 Key、调用模型、启动引擎或发送外部消息。构建出的单文件 HTML 用 CSP 禁止网络连接和表单外发。

构建使用仓库锁定依赖，不增加包：

```bash
node design/workspace-first/build.mjs
node --test test/workspace-first-design.test.mjs
node design/workspace-first/smoke.mjs
```

独立设计 worktree 没有安装依赖时，可给 build 指定 `--toolchain` 指向已有、正常 npm ci 的同源 Desktop 工作树。输出为 `.design-preview/workspace-preview.html`，可以直接离线打开。构建文件不作为正式应用包发布。

状态测试覆盖跨空间连接拒绝、草稿隔离、旧批准、到期与撤权、运行固定、独立验收、私人频道、AI 身份、档位不提权、消息分类和输出转义。事件 smoke 执行实际打包脚本与合成 DOM 适配器，验证按钮和表单事件，不是浏览器像素或系统安全验收。

正式上线前还必须完成：数据库和密钥箱迁移；服务端与宿主的完整隔离；真实旧版本恢复与撤权；多设备离线同步；390、860、1280、1440 宽度视觉与键盘验收；真实 Runtime 和 Desk 业务闭环。
