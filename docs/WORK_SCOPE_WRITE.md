# Work scope editing: C3 consumer boundary

This Desktop slice composes C0 duty/boundary documents for the existing C3 `duty.update` and `boundary.update` operations. C0 v1 remains unchanged. There is no production source binding, native credential bootstrap or Rust change in this slice. The composition root must authenticate the real Host before it supplies any bridge; a source factory, capability flag, JSON control projection or digest is never authentication or an execution permit.

The existing read source now has a validated immutable policy snapshot and current identity metadata for this consumer. Those contain C0 data and references, not server handles. Its ordinary `read()` projection still excludes context, rights and provenance from the card. Every asynchronous boundary rechecks the original capture; missing or revoked authority still yields no private card DOM or RPCs.

`work-scope-proposal.ts` reuses C0 parsers and the shared unconfirmed duty draft factory. A duty change preserves the boundary and four rights byte-for-byte. A boundary change preserves the duty and rights, rejects extra fields, duplicate resource references, overlapping allow/deny tools and an invented budget reference. User duty text never becomes a filesystem/tool permission. The difference list accounts for resource access, complete tool references, read-only mode, approval/required-check removal and budget increases; those widenings must be shown concretely before a C3 submission.

The C3 proposal digest is exact UTF-8 `hara-agent-policy-proposal-v1\0` followed by the Core canonical JSON. `sync-work-scope-proposal.mjs` copies the two pure Core JSON declarations without adaptation, locks the digest initializer/domain to Core b01e492, and generates ten vectors by executing that exact Core definition. WebCrypto is only an asynchronous SHA-256 adapter. Missing crypto fails closed. Author and reviewer checks must include `--check --core-repository` against the actual pinned Core source when updating this lock; the checked-in snapshot supports CI, not an alternative authority.

`work-scope-references.ts` persists only bounded, scoped IDs/digests/action names. A proposal, credential, complete command or raw context is rejected. Each command has its own storage key, so two windows cannot overwrite another possibly submitted operation. The caller must save its reference before attempting a submission. Malformed data, storage/quota errors and concurrent enumeration changes hold new work; unresolved references are never dropped by age or count. Removing a reference is reserved for a verified terminal original receipt. No storage code submits a command.

The writer and UI must preserve the original command ID after any possible submission, query only its original receipt after timeout/reload, and re-read the intended exact policy before claiming it is current. They must not reinitialize protected workspaces, call legacy configure/prepareProject on mount, create new grants or restart accepted/UNKNOWN work. Privileged production/bootstrap and packaged WebView joint acceptance remain separate C12 gates.


The implemented consumer is `work-scope-writer.ts`, composed explicitly with a registered read source, an authenticated `WorkScopeCommandPort` and an injected reference store. Both source and writer factories assign opaque instance lifetime keys; model-local versions or source-local serials alone must never identify a render. This fences a replacement source/model/writer synchronously, before passive effects clear state. Every async callback still rechecks its original connection capture. No generic `WorkspaceDevModel.request` method creates or binds a writer.

The privileged bridge must report revocation/connection changes synchronously, provide bounded RPC completion/rejection, and fence the exact observed owner connection. `inspect` is diagnostic management data, never a RunPermit. The current C3 capability and current `manage` right are required for editing; `manage` does not grant `privateRead`, `invoke` or `nodeUse`. Original C3 receipts follow Core's separate reader check. An optional edit catalog must come from the current Host registry/limits and use the same target/context/resource revisions. Unsupported connectors, native/exec/delegation tools and unregistered resource choices remain unavailable. C5 never calls configure, prepareProject, control.initialize or lifecycle reconciliation on mount.

Each session freezes the actual policy revision, C0 duty/boundary versions, target, context/provenance, rights, resource revisions and C3 agent epoch. Unrelated root-ledger revision changes are ignored so sibling progress cannot invalidate a still-identical policy. Every meaningful target/policy/epoch or catalog change requires another explicit review. The outgoing operation and draft wrapper are frozen before the Host callback. The Host must return the same IDs, operation digest, expected versions, context and observed provenance, with a valid exact command digest and live deadline. The immutable preview is owned by its writer's WeakMap; JSON copies are not preview handles.

Confirmation persists the bounded reference before any possible submit, and duplicate confirmations share one promise. An applied result is displayed as current only after an exact policy digest re-read, including C0 document revisions and all four rights. A verified original application followed by a different current policy is shown as superseded. Unexpected accepted/completed effects or an unknown drain in a policy receipt remain uncertain; they cannot retire the original reference even if another receipt field says rejected/applied. An unresolved, malformed or unidentifiable reference holds new changes. Restore/reconnect reads only original receipts and never reconstructs a private proposal or submits a replacement command.

`ColleagueWorkScopeEditor.tsx` provides separate responsibility and boundary forms, explicit before/after differences, widening warnings, expiry feedback and original-result recovery. Budget/check settings start collapsed while all proposed differences stay visible. Four-right editing, new grants, stop/approval/audit systems and production/native bootstrap are outside this consumer. The existing card retains its four sections and independently gated read path. A persistent live region announces loading, keyboard focus stays inside the modal in both directions, and cancel/discard/close return to safe controls. Draft/proposal text is rendered as text. The form uses the common duty draft factory shared with onboarding.

Author/reviewer verification uses the unchanged repository guard with private HOME/TMP, the pinned Node runtime, actual pinned Core source checks, focused/full tests and production frontend build. `scripts/work-scope-write-smoke.mjs` accepts `--core-repository`, `--core-ref`, `--scratch`, `--evidence` and optional `--host-only`; scratch must be inside an existing private guard scope. Its helper starts only a synthetic 127.0.0.1 Core C1/C3/C4 Host. The browser receives no owner credential or Core token, and a test-only same-origin/CSRF-bound adapter exposes only the narrow C5 methods. The private headless Chrome connects directly to loopback; this does not change the system proxy. Actual synthetic C2 file IO, old UNKNOWN facts and sibling run state are recorded separately from the zero-provider read/policy-update cases. Packaged WKWebView/VoiceOver, the supported macOS/package minimum and production C12 enablement still require their own release acceptance.

## Review recovery and native closing

New minimal local references use schema2 with the original Host draft issuedAt/notAfter. They contain no body, proposal or credential. The optional authenticated lookup port must also be advertised by the actual connection; legacy receipt reads remain supported. Only a strictly matching not_seen projection whose Core observation exceeds notAfter+1000ms retires the exact reference as local not_applied, never as a fabricated C0 receipt. Core observes under the same CAS lock, verifies hot/retired/history and uses its admission clock. Client time, age, errors, unavailable old Core and legacy references without deadlines cannot clear a reference. Seen accepted/UNKNOWN/effect observations stay held. Recovery never sends or reconstructs a new command automatically.

Native close restores the same dialog and focus while submitting/querying or confirming discard, including Chromium/WebView2's second non-cancelable Escape. Expiry cancels only an unsubmitted frozen preview, releasing its namespace; a possibly submitted promise/reference is retained. Actual browser regressions cover both Escape cases, an independent preview while the expired modal stays open, and unsent-reference reload after the real original deadline.

PR1 L1 is covered by work-scope-read's unknown/prototype tool-label cases with raw IDs under Advanced; PR1 L2 by the real persistent-live-region-through-loading matrix case. The hook-calls-visibleWorkScope assertion remains in work-scope-read. These are closed; native WKWebView/VoiceOver and trusted production bootstrap remain C12.
